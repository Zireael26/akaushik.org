# Decisions log

Decisions taken on the operator's behalf while running unattended at autonomy
L4. Newest first. Each entry says what was decided, what the alternatives were,
and what would have to be true to revisit it.

## 2026-08-23 — overnight preview-deploy run

### D1 · Preview host is `beta.akaushik.org`, not `dev.`
The operator offered either. `dev.` reads as "someone's machine" and is the
conventional name for a local or per-developer environment; `beta.` reads as
"the real thing, not finished", which is what this is — a shipped build of
unfinished design that other people may be shown. `dev.akaushik.org` stays free
for an actual development environment later.

### D2 · Worker name `akaushik-org-preview`, separate from `akaushik-org`
Two Workers rather than one Worker with two routes. A preview that shares a
Worker with production shares its logs, its analytics, and its rollback
history, and a bad `wrangler deploy` from the wrong shell would take production
with it. The blast radius of a separate Worker is the preview only. Matches the
`gaurijha-com` / `gaurijha-com-preview` pair already on this account.

### D3 · `production` env declared but not routed
`wrangler.jsonc` declares the production environment with no `routes`. Vercel
still serves `akaushik.org` and ADR-0018 keeps it paused-not-deleted for 14 days
after cutover, so pointing the apex at Workers tonight would be the cutover —
which is an operator decision, not a preview decision. Declaring it now means
the cutover is a route addition rather than a new config written under pressure.

### D4 · No incremental cache binding
`open-next.config.ts` calls `defineCloudflareConfig()` with no cache. The routes
carrying a `revalidate` window are the agent-surface JSON/Markdown routes and
the `md` suffix routes; all are cheap renders over MDX already in the bundle.
A KV incremental cache would add a second source of truth in front of content
that lives in files. Revisit if render cost shows up in Workers analytics.

### D5 · Compatibility date `2026-08-15`
Rather than today's date, which the Cloudflare docs suggest. 2026-08-15 is
already proven on this account by the `gaurijha-com` Worker, and a compatibility
date is a behaviour switch — taking the newest one on a first deploy means
debugging the adapter and the runtime semantics at the same time.

### D6 · Ported the agent-readiness contract into a Cloudflare Worker
Next 16 runs `proxy.ts` in the Node runtime and rejects `runtime: 'edge'`
outright; `@opennextjs/cloudflare` supports edge middleware only and aborts the
build when it finds a Node proxy. No version of either satisfies the other, and
1.20.2 is the newest adapter. ADR-0018 assumed edge middleware would carry over
and was wrong about that.

The alternatives were to move the Link headers and `.md` rewrites into
`next.config.ts` (possible) and give up the per-request nonce CSP (not
possible — ADR-0014 already rejected hashes), or to rewrite the contract twice.
Instead the policy moved to `lib/agent-proxy.ts` as pure functions with two
thin adapters over it: `proxy.ts` for `next dev`, `worker/index.ts` for
Cloudflare. `scripts/cf-build.mjs` parks `proxy.ts` during the Cloudflare build
and restores it in a `finally`.

Parking a source file mid-build is ugly and I want to be honest that it is. The
alternative was deleting `proxy.ts` and losing header parity in local
development, which would have made every local check meaningless. The policy
has 57 unit tests now where it had none, so the two adapters cannot drift on
anything that matters.

### D7 · Content is inlined into the bundle instead of read from disk
`lib/content.ts` used `readFileSync` at request time. Workers have no
filesystem — `node:fs` there is an empty per-request scratch space — so every
`/work/<slug>` and `/writing/<slug>` returned 404 while the prerendered index
pages looked healthy. Prerendering the content pages was not available:
`app/layout.tsx` reads `headers()` for the CSP nonce, which makes the entire
route tree dynamic. The generated bundle is 126 KB and is committed, because a
fresh clone must typecheck before `prebuild` has run.

### D8 · MDX compiles at build time; `next-mdx-remote` is no longer the renderer
With content reachable, the same pages returned 500. `next-mdx-remote` compiles
per request and evaluates with `new Function`, which Workers refuse; Shiki's
oniguruma engine instantiates WebAssembly from bytes, refused for the same
reason. Both are runtime-compilation problems, so both were moved into the
build. This added `@mdx-js/mdx` as a devDependency — a new dependency, which I
would normally raise first, but the site does not deploy without it and it is
the compiler `next-mdx-remote` was already using transitively.

Compiled output is git-ignored and regenerated by `prebuild`, `pretypecheck`
and `pretest`, so nothing can consume a stale copy. `stripTitleChrome` moved to
`lib/strip-title-chrome.ts` so the generator and the article template cannot
disagree.

### D9 · Cropped the portrait rather than retuning the ramp
The portrait rendered as a lime slab with a hole in it. The cause was the
photograph, not the engine: with `invert` on, the black polo shirt — the
largest single-tone region in the frame — took the loudest end of the palette
while the face landed mid-ramp. `fromImage` takes a `crop` now, applied before
the auto-contrast stretch so the stretch runs over the subject rather than the
room. I put the option on the shared image source rather than on the portrait
component, because every image the pixel system converts will need it.

Four iterations against a screenshot, not reasoning: crop, floor, and cell size
were each tuned by looking. Final values are in `components/sections/About.tsx`
with the reasoning next to them.

### D10 · No Vercel changes tonight
`akaushik.org` still serves from Vercel and I did not touch that project. The
preview proves the Workers path end to end, but pointing the apex at it is the
cutover, and ADR-0018 puts a 14-day paused-not-deleted window on the Vercel
project after that. That is a decision to take awake.
