- 2026-08-23 — Recorded ADR-0019 (`docs/adr/0019-workers-runtime-constraints.md`), Accepted 2026-08-23, supersedes nothing and constrains future work. Documents three Cloudflare Workers runtime constraints and their build-time resolutions: Next 16 `proxy.ts` is Node-only — `runtime: 'edge'` is rejected with “Proxy does not support Edge runtime” — while `@opennextjs/cloudflare` supports edge middleware only and aborts with “Node.js middleware is not currently supported”, so the agent-readiness contract is pure `lib/agent-proxy.ts` with thin `proxy.ts` and `worker/index.ts` adapters and `scripts/cf-build.mjs` parks `proxy.ts` for the Cloudflare build; runtime filesystem reads produced content 404s, so `scripts/build-content-bundle.ts` emits committed `lib/content-bundle.generated.ts`; runtime `next-mdx-remote`/`new Function` and Shiki WASM produced 500s — “EvalError: Code generation from strings disallowed for this context” and “Wasm code generation disallowed by embedder” — so `scripts/build-mdx-modules.ts` emits ESM and `stripTitleChrome` lives in `lib/strip-title-chrome.ts`. Consequences are load-bearing: no runtime code may compile templates, instantiate WebAssembly from bytes, call `new Function`/`eval`, or read the filesystem, and MDX plugin changes belong in `scripts/build-mdx-modules.ts`, not `lib/mdx-options.ts`.
