## The thing to know before touching anything

Three Cloudflare Workers constraints bit during the deploy, all recorded in
ADR-0019 and in `docs/CHANGELOG.md`:

1. **No Node middleware.** Next 16 removed the edge runtime from `proxy.ts`;
   OpenNext supports nothing else. The agent-readiness contract lives in
   `lib/agent-proxy.ts` as pure functions, with `proxy.ts` (local) and
   `worker/index.ts` (Cloudflare) as thin adapters. Change policy in the pure
   module, never in one adapter.
2. **No filesystem.** `lib/content.ts` reads from
   `lib/content-bundle.generated.ts`, produced by
   `scripts/build-content-bundle.ts`. The generated file is committed.
3. **No runtime code generation.** No `new Function`, no `eval`, no
   WebAssembly instantiated from bytes. MDX compiles during the build via
   `scripts/build-mdx-modules.ts` into `lib/mdx/generated/` (git-ignored,
   regenerated by `prebuild`, `pretypecheck` and `pretest`). If you add an MDX
   plugin, add it in that script — `lib/mdx-options.ts` no longer renders
   anything.

## Commands

- `pnpm cf:build` — parks `proxy.ts`, builds the Worker, restores it. If it
  ever leaves `proxy.ts.cf-parked` behind, move it back by hand.
- `pnpm cf:deploy:preview` — build and deploy to `beta.akaushik.org`.
- **Every Wrangler call needs `env -u CLOUDFLARE_API_TOKEN`.** The zone-scoped
  token in the shell profile shadows the OAuth session Wrangler actually has.
  No token needs minting; this is the whole obstacle.

## Caveat on the e2e suite

**Firefox cannot run on this machine, and it is not the site's fault.**
Playwright's bundled Firefox Nightly fails at launch under the macOS sandbox:

```
sandbox_extension_issue_file_to_process failed for .../plugin-container.app:
  1 (Operation not permitted)
Crash Annotation GraphicsCriticalError:
  RenderCompositorSWGL failed mapping default framebuffer, no dt
```

Every `page.goto` then hangs until timeout, which is why two full five-project
runs stalled — the `request`-based specs pass and the first spec that loads a
page never returns. Fixing it is a Playwright/macOS permissions problem, not a
code problem, and it is worth fixing because it currently makes any local
five-project run useless. WebKit and Chromium both launch and load the site
normally.

Where that leaves coverage: two engines, both green.

- `chromium-desktop` — 60 passed, 1 documented fixme, 0 failed.
- `webkit-desktop` — 22 passed, 39 skipped, 0 failed. The skips are all
  `test.skip(browserName !== 'chromium', …)` guards the specs already carried;
  they are by design, not by failure.

Do not read those as five-browser coverage: `firefox-desktop`,
`chromium-tablet` and `webkit-mobile` have not run.
